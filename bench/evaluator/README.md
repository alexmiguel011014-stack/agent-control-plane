# Offline evaluator interface

All 40 benchmark suites are bounded declarative JSON graphs. The host parses them with a fixed schema and materializes only allowlisted object, array, Map, Error, TypeError, AppError, undefined, BigInt, and no-op fixture values; case files are never imported or executed. Expected values stay on the trusted host, and only `callId`, `operationId`, and `args` cross the bounded JSON protocol to the AppContainer worker. G0 execution is reachable only through the `bench/evaluator/index.mjs --run --approve-review-set-sha256 <sha256>` CLI after current G2.2 evidence and an exact byte-for-byte match of the generated owner review index. The worker resolves operations from its fixed registry and never reads repository attestation files or executes host case modules. G2.2 still requires evidence that verifies the actual worker launcher.

Only the gated `benchmark:g0:run` flow creates the production evaluator. It requires the explicit approved review-set hash, the exact 20 corpus records loaded after approval, and current G2.2 evidence. `source: "model"` is rejected by the first guard; missing review authorization or stale isolation evidence fails closed before task lookup.

There is no generic evaluator factory or request-level dependency override. The production evaluator binds each task closure to its approved digests and checks the task manifest, snapshot manifest and ID, patches, public case data, and oracle data before evaluation. It checks the corpus, host baseline, runtime fingerprint, and G2.2 evidence again before generating the G0 report.

The harness validates the task manifest, checks the task ID against fixed public-case and oracle registries, verifies the content-addressed snapshot before and after restoration, restores into a fresh temporary directory, and applies only the task's local patch. The null patch must be empty. It parses the full unified diff before writing, rejects paths outside `allowed_globs`, and checks the actual changed-file list and limit. The host runs both fixed case sets through `runHostCases`; only calls go to the AppContainer worker, while expected values and comparisons stay on the host. Aggregate `PASS` requires both case sets to pass. Task, public-case, and oracle-case inputs are hashed before and after evaluation; task-local `oracle/` directories and missing global oracle files are rejected.

This is a benchmark harness, not a sandbox or OS security boundary. A fresh directory, a path allowlist, hashes, and AppContainer integration do not prove filesystem containment, network denial, or termination of descendants. Evaluations of `null` or `reference` sources fail closed unless the current G2.2 attestation matches the host baseline and runner fingerprint. `benchmark:g0:prepare` performs static corpus validation, snapshot restore checks, patch parsing, and creates the owner review index plus `bench/results/g0-preflight-report.json`; it does not apply patches or run public or oracle cases. Its report stays `BLOCKED_G2.2`.

`test:benchmark-contract` runs only static schema, snapshot, digest, policy, parsing, and attestation-validation tests. `test:evaluator:post-g2.2` remains behind its attestation gate and contains only pure digest/status checks; it does not inject a fake attestation, worker, or case runner into the production evaluator. `benchmark:g0:run` requires current G2.2 evidence and the approved review-set hash. Do not run the benchmark before G2.2 evidence exists and has been reviewed.
