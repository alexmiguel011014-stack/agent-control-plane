# Benchmark task manifests

Every host-side registered public-test module awaits the shared G2.2 entry gate before dynamically importing candidate code or registering node:test cases. Direct invocation fails closed without current evidence. Static contract tests inspect all 20 modules as text and never load task tests or oracles. The future isolated worker receives bounded JSON from the host and must not read repository attestation files or run these host-side modules; G2.2 must verify its launcher separately.

Task fixtures are original, local, and reproducible. The task manifest contract is defined by [`../schema/task.schema.json`](../schema/task.schema.json), JSON Schema draft 2020-12. Before G2.2, `npm run test:benchmark-contract` is static-only: it may validate schemas, snapshots, manifests, patch syntax, and report hashing, but must not apply any patch or run task/oracle code. The evaluator behavior suite is `npm run test:evaluator:post-g2.2`; it must fail closed unless the G2.2 host/runner attestation is valid.

Each task directory contains `task.json`, `base/`, and a sibling `snapshot.json`. Its task manifest identifies a stable `task_id`, the agent-visible `prompt`, the content-addressed `base_snapshot_sha256`, allowed relative POSIX `allowed_globs`, closed `allowed_operations`, a registered `public_test_command_id`, execution limits, `oracle_version`, and `risk_class`. The manifest stores a test **identifier**, never a command string; the harness maps identifiers to fixed commands.

Snapshot v1 enumerates regular files in `base/` using normalized relative POSIX paths. The canonical manifest is `{schemaVersion:1,files:[{path,sizeBytes,sha256}]}`, sorted by ordinal path order with no timestamps. The snapshot ID is lowercase SHA-256 of the UTF-8 compact `JSON.stringify` representation of that canonical object. `snapshot.json` is next to `base/`, outside the bytes it describes. Use [`../snapshots/index.mjs`](../snapshots/index.mjs) to create/write/read/validate manifests, verify file bytes and IDs, and restore a verified base into a new empty directory offline. Restore never overwrites or deletes a destination.

After fixture files are final, `node bench/snapshots/seal.mjs` writes each task's sibling `snapshot.json` and updates only that task's `task.json` `base_snapshot_sha256`. Use `node bench/snapshots/seal.mjs --check` for a read-only consistency check; it exits nonzero if any ID or deterministic manifest is stale.

The static preflight and owner-only review index are generated with `npm run benchmark:g0:prepare`; this does not apply patches or execute task tests. The index binds the full review set (task manifests/prompts, snapshots, public tests, oracles, patches, evaluator, and protocol) and contains no patch code or oracle data, so it must never be copied into model context. Review every linked reference patch and approve the current full review-set hash. `npm run benchmark:g0:check-windows` checks snapshot handling of Windows junctions and writes evidence under ignored `runtime/diagnostics/`; it does not satisfy the G2.2 OS-isolation gate. Only after G2.2 passes and the owner approves the exact current hash may the operator run `npm run benchmark:g0:run -- --approve-review-set-sha256 <hash>`. G2.3 runs only null/reference sources; a reference passes only if both its public tests and hidden oracle pass. This evaluator is not an OS sandbox.

Hidden oracle case data lives in `bench/oracles/ID.json` (where ID is the task ID), outside the task directory tree and outside the candidate context. Public and oracle cases use bounded declarative JSON graphs; the host materializes fixed types and never imports case modules. `task.json` must not contain an oracle path; the evaluator selects oracle files through its fixed internal task-ID registry. The future integration may provide the candidate only the task prompt, restored `base/`, and public case data. Never copy, enumerate, or pass oracle files into that context. Do not put hidden assertion text, expected patches, credentials, or personal data into the agent context. Fixture bases and reference patches are agent-authored; independent static review is required. Owner approval binds only the exact full review-set hash; any change to a bound artifact requires fresh approval. Git commits are not required as benchmark bases; no automated agent creates commits.

The snapshot implementation rejects symlinks/junctions or other non-regular entries, absolute/traversal paths, `.env*`, `.git`, unsupported characters, and case-insensitive path collisions. Runtime policy must still resolve paths and reject junction/symlink escapes; schema and snapshot validation are input/integrity checks, not an OS sandbox. Before G2.2, no agent-authored patch (including synthetic, null, or reference patches) may be applied or tested, and no task public test or hidden oracle may run against patched code. After G2.2, G2.3 may run only owner-approved null/reference fixtures; `source=model` remains unavailable for the G0 closure. Network access and arbitrary shell commands are not task operations.
